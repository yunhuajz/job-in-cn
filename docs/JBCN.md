# JBCN 本机求职工具

在 PowerShell 中输入 `JBCN`，服务绑定 `127.0.0.1:3737`，就绪后自动打开岗位页。再次输入会复用已有服务。首次启动或源码、构建配置变化后会构建本机服务，可能等待几十秒；日常启动直接复用构建。新增岗位、修改采集条件不会触发构建。构建失败或产物被其他构建替换后会重新构建。

本机模式沿用现有唯一账号的数据，无需注册或登录。若数据库有多个账号，设置 `JBCN_USER_ID` 明确选择，不自动合并账号。首次在已迁移的空数据库上启动会初始化本地账号和岗位状态。

## 使用

- **岗位**：按关键词、城市、来源、具体地点、薪资及双休筛选；每页 25 条，可查看详情和原招聘页。
- **AI 设置**：按接口协议配置 OpenAI Responses、OpenAI Chat Completions 或 Anthropic Messages，填写 Base URL、API Key 和模型名。模型名可自由填写，也可从兼容服务的 `/models` 接口获取。岗位页选择一批岗位后可执行 LLM 评分；评分使用当前默认简历，结果写回岗位的匹配分和评估报告。
- **爬虫**：分别配置 Boss、前程无忧、智联，保存后可手动开始/停止。关键词和城市支持多行或逗号分隔；每组最多 1–50 条。
- 关键词、城市用于平台搜索；具体地点、薪资、双休在入库前筛选。智联未收录城市码的城市使用全国搜索后筛选，页面和日志会说明；可直接填写网站城市码。
- 最低薪资模式要求招聘月薪范围的**上限**达到用户下限；区间模式要求两个范围有重叠。日薪、时薪、年薪和面议不擅自折算，按未知处理。
- 双休根据明确的 JD 表述或已确认状态判断，问句不算确认。默认保留未知条件，可取消勾选。
- 同一时间只运行一组采集任务。点击停止后，等待当前浏览器操作结束，不开始下一条；关闭页面不会停止任务。服务重启后运行状态清空，配置和已入库岗位保留。
- 详情间隔 20 秒，搜索组合间隔 3 分钟。遇到操作错误会停止并显示原因；连续两组空结果也会停止，便于检查验证页或搜索条件。

招聘网站仍需在日常 Chrome 中登录并连接 OpenCLI Browser Bridge。验证码由用户在浏览器处理。采集不会发送招呼或 HR 消息。本机模式不启动原有定时招聘扫描器。

## 文件与安装

- 岗位数据库：`apps/web/prisma/dev.db`（沿用现有 `DATABASE_URL` 配置）。
- 岗位、评分、求职进度和采集日期持久保存在数据库，关闭页面或服务不会删除。备份时先执行 `JBCN stop`，再复制数据库文件；若存在同名 `-wal`、`-shm` 文件，一并保留。
- 采集配置：`data/crawler/boss.json`、`job51.json`、`zhaopin.json`；首次用画像里的关键词和城市初始化，之后独立保存。
- 服务日志：`data/jbcn.log`。
- 启动：`JBCN`；仅启动不打开浏览器：`JBCN --no-open`（项目内命令对应为 `.\JBCN.cmd`）。
- 关闭服务：`JBCN stop`，或在项目目录中输入 `.\JBCN.cmd stop`。它会先确认端口上是本项目的 JBCN 服务，再结束该服务。
- 注册全局命令：`powershell -NoProfile -ExecutionPolicy Bypass -File scripts/install-jbcn.ps1`。写入当前用户 npm 命令目录，必要时加入用户 PATH；无需管理员权限。新开 PowerShell 后使用 `JBCN`。
- 默认端口被其他程序占用时明确报错，不停止其他服务；可设置 `$env:JBCN_PORT='3738'`。

当前为源码启动版本，依赖 Node.js ≥22、根目录和 `apps/web` 已安装的依赖，以及已执行迁移的数据库。尚未制作独立安装包。

## 多平台采集与岗位进度

- 可启用 Boss、前程无忧、智联中的一个或多个平台；每完成一个“关键词 × 城市”搜索组，就轮转到下一个启用平台。
- 轮次数可设置为 1–10，默认 1；Boss 和前程无忧在后续轮次读取下一页。智联当前适配器没有可靠的后续页能力，会写入日志并跳过后续轮次，避免把同一页误作新增。
- 每个搜索组结束后等待 3 分钟再轮转平台；详情之间维持原有 20 秒间隔。
- 支持暂停 1 小时或 2 小时，并显示恢复时间；当前浏览器操作结束后不再开始下一条。普通暂停到时自动恢复。
- 验证码、掉线或风险提示会暂停对应平台，其他平台继续。处理后可在页面点击“恢复已暂停的平台”。
- 运行中的任务会保存当前搜索组；服务重启后页面显示“继续上次采集”，从中断组重新开始，已收录岗位会去重。
- 搜索列表阶段先按岗位链接跳过已收录岗位，再打开新候选岗位详情；同一岗位不重复创建主体数据，但每次采集都会留下日期记录。岗位页可按采集日期查询，并显示首次收录与最近采集时间。
- 岗位进度为“未投递”“投递过”“深度推进中”“收到 offer”，可按进度筛选并批量更新。重复采集不会覆盖进度。
- 评分按 1–5 分筛选和排序，未评分可单独筛选，且按评分排序时排在最后。
- “自动投递 Boss”只处理当前页中已选择的 Boss 未投递岗位，并要求浏览器弹窗明确确认。只有沟通成功经网站验证后才标记为“投递过”；未能确认的岗位保持原进度。
- 岗位页的求职进度作为常驻快捷筛选显示；评分、采集日期、薪资、地点和双休放在“更多筛选”。“LLM 评分”每批最多处理 10 个岗位，未配置模型、凭据或默认简历时会明确提示。
- 招聘网站账号由用户自行切换登录，程序只使用当前 Chrome 登录状态，不管理或自动切换账号。
