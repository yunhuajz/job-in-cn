# PRD — job-for-claude(AJS)

> 状态:Draft v0.2 · 2026-07-22(替代 v0.1:v0.1 的 N1「不做自动投递」等已被 ADR-0001 推翻)
> 性质:产品需求文档(做什么、给谁、为什么)。架构决策见 `docs/adr/`,领域术语见 `CONTEXT.md`,代码约定见根 `CLAUDE.md`,三参考仓库分析见 `../../docs/`。

## 1. 概述

job-for-claude 是一个**以 Claude Code 为中心的个人 AI 求职系统**,面向中国市场,**以 Boss 直聘为主要平台**。

用户白天上班,PC 在家自动扫描 Boss 新职位并无人值守评分;晚上回家在「今日汇总」里一眼过完当天职位,批量圈选批准后,bot 以人化节奏自动发招呼语投递;JD 没写明的双休/节假日/薪资,随招呼语向 HR 确认,回复自动回填。全程结果落到本地 jobsync Web 应用可视化。

一句话:**Claude Code 是大脑,jobsync 是显示器,Boss provider 是手脚。**

| 组件 | 角色 | 形态 |
|------|------|------|
| **Claude Code** | 大脑 / 协调器 / 对话入口 | 用户唯一交互界面 |
| **Boss provider**(新写) | 扫描 + 投递 + 收回复(Playwright) | `src/boss/`,绿地 |
| **jobsync**(fork) | 显示 + 持久化 + MCP server | 原生 npm 进程(非 docker),扩展 MCP tool |
| **career-ops**(参考) | 读侧模式 / 评估框架 / 招呼话术 / 复盘的**来源** | 选择性搬代码 + 引用(ADR-0003) |
| **ai-job-search**(参考) | 简历生成方法论的**来源** | 引用其 skills(ADR-0003) |

## 2. 背景与问题

- Boss 直聘的 JD **常不写双休/节假日**,且不少公司实际不遵守 —— 需要投递前向 HR 确认。
- 三个参考仓库各有残缺(见 `../../docs/` 三份分析),且**全部明确不做自动投递**;Boss 平台三家均无支持(绿地)。
- 用户是白天上班的个人求职者,只有晚上能处理求职 —— 需要「白天自动准备,晚上集中决策」的节奏。

## 3. 目标用户

- **中国的技术岗个人求职者**,白天上班、晚上处理求职,PC 白天在家常开。
- 已在用(或愿意用)Claude Code;投递量中等以上,需要看板管理。
- 隐私敏感:数据全在本地 PC。单用户场景。

## 4. 目标与非目标

### 目标(Goals)

- G1 所有求职交互在 Claude Code 对话中完成。
- G2 Boss 直聘全流程闭环:扫描 → 评分 → 汇总 → 批准 → 投递 → HR 确认 → 追踪。
- G3 **每日节奏**:早上开机扫描 + 白天定时扫描 + 无人值守评分(便宜模型);晚上「今日汇总」+ 批量批准。
- G4 **A2 自动投递**:批量批准后 bot 人化节奏发招呼语(Boss 预存一版常用语,一键发送);JD 缺双休/节假日/薪资时系统只标记缺失,确认问句由本人在 HR 回复并交换简历后的对话中发出;HR 回复只读回填。
- G5 定制简历生成对齐 ai-job-search 方法论。
- G6 jobsync SQLite 为唯一真相,全程可视化追踪。
- G7 **账号安全**:零封号(人化频率、单账号、验证码交人、风控熔断,ADR-0002)。

### 非目标(Non-goals)

- N1 **不做全自动投递(A3)**;**不做自主 HR 对话(B2/B3)** —— 人永远挡在「投给谁」与「跟 HR 说什么」两道闸前(ADR-0001)。
- N2 不做云托管 / 多租户 SaaS。
- N3 不重写三组件核心代码(只搬小块 + 引用 + fork jobsync 扩 MCP)。
- N4 不启用 jobsync 自带 AI 功能(job-match / resume-review / automation-match)。
- N5 不做多平台并行:Boss 先行,智联/前程无忧等放 P5 之后。
- N6 不做海投:评分低于阈值的职位不进入批准清单。

## 5. 核心能力与用户故事

| # | 作为求职者,我想… | 由谁完成 |
|---|----------------|---------|
| US1 | 早上开机自动扫描 Boss 新职位(补昨夜),白天再定时扫两次 | 任务计划程序 + Boss provider(只读) |
| US2 | 每个新职位白天就评好分(1–5 + 评估报告),不用我等 | 无人值守评分(便宜模型)→ MCP 写回 |
| US3 | 晚上打开「今日汇总」:职位 + 评分 + 城市 + 薪资 + 双休状态,一眼过完 | jobsync 视图 |
| US4 | 批量圈选批准后,bot 自动发招呼语投递,不用我一个个点 | Boss provider 写侧(A2 闸) |
| US5 | JD 没写双休/节假日/薪资的,系统标记缺失信息;HR 回复后自动把确认结果填回字段 | 缺失标记 + 只读回复捕获(询问由本人在手机 App 进行) |
| US6 | 对要投的职位生成定制简历(质量过关) | ai-job-search 方法论(P4) |
| US7 | 在看板上看每个职位的状态流转(待确认/已投/已回复/面试/Offer/已拒) | jobsync UI |
| US8 | 复盘拒绝模式,调整投递策略 | career-ops patterns 模式(P5) |

## 6. 架构概览

全部跑在用户 Windows PC,零容器、零云依赖:

```
            用户(晚上,对话)
                │
                ▼
        ┌───────────────┐
        │  Claude Code  │ ◄── 唯一入口 / 大脑
        └──┬─────────┬──┘
    调用    │         │  MCP (localhost:3737)
           ▼         ▼
  ┌─────────────┐  ┌──────────────────────┐
  │ Boss provider│  │ jobsync(fork,原生)  │
  │ Playwright  │  │ MCP server + 5 列契约 │
  │ 网页端       │  │ dev.db = 唯一真相     │
  │ 读:扫描/JD   │  │ 看板/汇总/简历库      │
  │ 写:招呼语(A2)│  └──────────────────────┘
  └─────────────┘            ▲
  任务计划程序定时触发(只读)──┘
```

- **读侧**(扫描/JD 抽取/收回复):可无人值守,零消息零风险。
- **写侧**(发招呼语):永不进定时任务,只在用户批量批准后执行(ADR-0001)。
- 数据契约:jobsync fork 的 `Job` 只加 5 列,评分 ×20 映射 matchScore(ADR-0005)。
- 决策细节:自动化档位 ADR-0001、Boss 技术方案 ADR-0002、仓库结构 ADR-0003、fork ADR-0004、数据契约 ADR-0005。

## 7. 范围与阶段

| 阶段 | 交付 | 验收 |
|------|------|------|
| **P0 地基** | jobsync fork 原生跑通(无 docker);5 列迁移;MCP tool 扩展(update_evaluation / set_status / save_resume_version / add_note / list_jobs);Claude Code 连上 MCP | Claude Code 能通过 MCP 增查改 jobsync 数据 |
| **P1 Boss 读侧** | Playwright 登录态(QR 持久化);搜索→JD 抽取→落 jobsync;真实 UA + 随机间隔;城市/薪资填充 | 手动跑一次扫描,职位进收件箱 |
| **P2 每日节奏** | 任务计划程序(登录触发 + 白天 2 次);无人值守评分(便宜模型)写回;「今日汇总」视图 | 早上开机,晚上回家看到带分汇总 |
| **P3 写侧 A2(核心)** | 批量批准 → 招呼语(Boss 预存一版常用语)→ Claude Code + chrome-devtools MCP 一键发送(用户在场);人化频率 ≤20/天;验证码交人;风控熔断;HR 回复只读捕获回填 | 批准 3 个职位,自动投出且账号无恙;「待确认」职位的 HR 回复正确回填 |
| **P4 简历生成** | ai-job-search 方法论接入;定制简历存 Resume 挂到职位 | 对 ≥4.0 分职位一键生成定制简历 |
| **P5 复盘 + 扩展** | 拒绝模式分析上仪表盘;智联/前程无忧等新 provider;可选迁移到家里常开 Linux 小主机 | —— |

## 8. 成功指标

- **节奏闭环**:早扫描 → 晚汇总 → 批准 → 投递,全流程无手工搬运。
- **账号安全**:连续 30 天零风控警告、零封号。
- **汇总就绪率**:晚上回家时 ≥90% 当日新职位已带评分。
- **数据完整**:已投递职位 100% 有招呼语记录与状态轨迹。
- **频率合规**:每日投递 ≤20 条,间隔 30s–3min,仅 9:00–21:00。

## 9. 主要风险

| 风险 | 缓解 |
|------|------|
| Boss 封号 | ADR-0002 全套:人化频率、单账号、真实 UA、验证码交人、风控熔断 |
| 登录态失效(QR 过期) | 扫描失败即通知,手动扫码恢复;storageState 持久化 |
| fork jobsync 的 merge 成本 | 改动集中边缘目录;维护「我们改过的文件」清单(ADR-0004) |
| 数据损坏/丢失 | jobsync dev.db 唯一真相;备份 = 拷一个文件 |
| 白天无人值守评分的 API 成本 | 便宜模型(DeepSeek/GLM 级),每日几毛钱量级 |
| PC 关机导致扫描缺失 | 任务计划程序「错过补跑」;晚上手动 `/scan` 兜底 |
