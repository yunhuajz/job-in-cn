# 自动化投递档位:批量批准后自动投(A2),HR 确认由本人对话发出、回复只读(B)

**Status**: accepted(2026-07-22;2026-07-24 修订)

Boss 直聘的自动化定为两档:**投递走 A2** —— 用户在看板批量圈选批准后,bot 按人化节奏自动逐个投出(招呼语为 Boss 预存的一版常用语,一键发送,不附带确认问句);**双休/节假日/薪资确认走 B** —— 确认问句不进招呼语(初轮盘问不礼貌),而是在「HR 回复 → 交换简历」后的自然对话中由候选人本人发出,系统只标记 JD 缺失信息、只读捕获回复并回填字段。永不做全自动投递(A3)与自主 HR 对话(B2/B3)。

## 背景与权衡

三个参考仓库(ai-job-search / career-ops / jobsync)都明确「不替用户点投递」,本决策是有意反转这一原则,换取自动化;但保留「人决定投给谁」这道闸,避免海投与机器人行为特征。HR 对话自动化的封号风险与欺骗成本(对面是真人)过高,因此只起草、只读收,不自主对话。

**2026-07-24 修订说明**:原方案把确认问句塞进招呼语,实践中初轮招呼即盘问双休/薪资不礼貌、可能降低 HR 回复率;且 Boss 的真实沟通节奏是「打招呼 → HR 要简历 → 发简历 → 自然开聊」,确认问题在简历交换后提出才合乎礼仪。故确认动作后移并完全交还候选人本人,系统职责收缩为:标记缺失信息、捕获回复、回填字段。

## 被拒绝的替代方案

- **A3 全自动**(bot 自行发现→评估→投):Boss 行为风控下近似封号直通车。
- **B2/B3 自动发 HR 消息/自主谈判**:聊天是 Boss 反作弊重灾区,且让 bot 冒充用户与真人对话有欺骗性质。
- **确认问句塞进招呼语**(原 B 方案,2026-07-24 废弃):初轮盘问不礼貌,违背真实沟通节奏。
